# Error Handling & Status Codes

## 1. Overview

**WORKHUB** implements a standardized HTTP exception strategy adhering strictly to RFC 9110 HTTP Semantics. All client-facing errors provide deterministic JSON response structures with meaningful error messages.

---

## 2. Standard Error Response Format

Whenever an API operation fails, FastAPI formats the error payload consistently:

```json
{
  "detail": "Description of the error"
}
```

For validation errors generated by Pydantic:

```json
{
  "detail": [
    {
      "type": "string_too_short",
      "loc": ["body", "password"],
      "msg": "String should have at least 6 characters",
      "input": "123"
    }
  ]
}
```

---

## 3. Status Code Reference Table

| Status Code | Meaning | When It Is Raised | Example Trigger |
| --- | --- | --- | --- |
| **200 OK** | Success | Successful read, update, or deletion | `GET /employees/`, `POST /auth/login` |
| **201 Created** | Resource Created | Successful creation of a new entity | `POST /employees/`, `POST /auth/register` |
| **400 Bad Request** | Invalid Input | Malformed JSON or invalid syntax | Broken JSON body syntax |
| **401 Unauthorized** | Authentication Failed | Missing, invalid, or expired JWT token | Expired token on `GET /employees/` |
| **403 Forbidden** | Access Denied | Authenticated user is inactive or blocked | User with `is_active = False` |
| **404 Not Found** | Resource Missing | Target record does not exist | `GET /employees/9999` |
| **409 Conflict** | State Conflict | Unique constraint violation | Registering with an existing email |
| **422 Unprocessable Entity** | Schema Validation Error | Payload fails Pydantic schema rules | Invalid email format or missing fields |
| **500 Internal Server Error** | Unexpected Failure | Database connectivity loss or uncaught exception | Unreachable PostgreSQL host |

## 4. Error Handling Best Practices in Code

### 1. Fail Fast in Services

Business errors are caught early in the service layer using explicit `HTTPException`:

```python
if existing_user is not None:
    raise HTTPException(
        status_code=status.HTTP_409_CONFLICT,
        detail="Email already registered"
    )
```

### 2. Structured Exception Logging

Database errors in `connection.py` are logged with full stack traces using `logger.exception()`:

```python
try:
    with engine.connect():
        logger.info("PostgreSQL connected successfully!")
except Exception:
    logger.exception("PostgreSQL connection failed!")
    raise
```

This guarantees that operational failures are immediately visible in terminal monitoring systems without revealing internal connection credentials to the API client.
